# 技术栈速览

## 一次请求要跨过哪几道关

---

## 浏览器点「注册」之后

后端要依次回答几个问题：

- 这段 JSON 合法吗？
- 字段类型对吗？能入库吗？
- 数据存在哪张表？
- 返回给前端的格式是什么？
- 接口文档在哪？

每一关都能手写，也都能交给现成的工具。

---

## 四个包，各管一段

| 包 | 负责哪一关 | 一句话 |
| --- | --- | --- |
| [**Pydantic**](/?src=decks/Pydantic.md) | 数据可信吗 | 用类型描述并校验数据 |
| [**SQLModel**](/?src=decks/SQLModel.md) | 数据怎么存 | 一个类同时是表和模型 |
| [**FastAPI**](/?src=decks/FastAPI.md) | 接口怎么暴露 | 类型注解直接变成接口 |
| uvicorn | 谁来收请求 | ASGI 服务器，把应用跑起来 |

它们共享同一个底座：**Python 类型注解**。

---

## Pydantic：数据可信吗

```python
class User(BaseModel):
    name: str
    age: int = Field(ge=0, le=150)
```

- 声明式校验，不用写一长串 `if`
- 能转换的自动转（`"30"` → `30`）
- 出错时精确指出是哪个字段

---

## SQLModel：模型要写两遍吗

```python
class Hero(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    name: str
```

- 一个类 = 数据库表 + 校验模型
- 不用再手写「表字段」和「接口字段」两套
- 底层仍是 SQLAlchemy，能力没变

---

## FastAPI：接口和文档一起出来

```python
@app.post("/users")
def create_user(user: User):
    return user
```

- 参数从函数签名里读，不用自己解析
- 校验交给 Pydantic，失败自动 422
- 打开 `/docs`，接口和 schema 已经在那了

---

## uvicorn：谁来监听端口

```bash
uvicorn main:app --reload      # main 是文件名，app 是实例
```

- 你写的是「应用对象」，不是服务器
- uvicorn 负责收 HTTP、转成 ASGI、调度并发
- `--reload` 只在开发时用

---

## 串起来：一次请求的路径

1. **uvicorn** 收到 HTTP 请求
2. **FastAPI** 匹配路由，取出参数
3. **Pydantic** 校验并转换请求体
4. 业务代码执行，**SQLModel** 读写数据库
5. **Pydantic** 序列化返回值
6. uvicorn 写回响应

任何一步类型不对，都会在进入业务代码前被拦下。

---

## 最小可运行示例

```python
from fastapi import FastAPI
from sqlmodel import SQLModel, Field, Session, create_engine, select

class Hero(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)
    name: str

app = FastAPI()
engine = create_engine("sqlite:///hero.db")
SQLModel.metadata.create_all(engine)

@app.get("/heroes")
def list_heroes():
    with Session(engine) as s:
        return s.exec(select(Hero)).all()
```
